# 世界工坊

运行 `engine:serve` 后打开 `/world-builder`，或者点击角色控制台左侧的“世界工坊”。无需访问令牌；页面是新世界配置编辑工具。

## 第一次使用

1. 页面自动载入中文河谷样例。先修改世界名称和新世界编号。
2. 在“地点与商店”选择或添加地点，修改名称、资源、危险程度和商店设置。
3. 在“连接道路”选择两个不同地点。连接可以双向通行，重复道路会被阻止。
4. 添加初始人物，选择种族、出生地点和资源；调整工作、采集、移动、训练与休息规则。
5. 预览选中地点、相邻道路、人物和组织。检查通过后点击“下载可用配置”。

地点仍被人物、组织、道路、观察者起点或商店引用时不能删除。组织成员不能直接删除，需要先在完整配置中解除关联。删除和其他修改可以撤销；保留最近最多 20 步，历史内容约 5 MiB，单个大配置最多保留一份历史。

“打开配置”支持 UTF-8 JSON、最多 1 MiB。多模板包先检查整个包，再由用户明确选择编辑哪个模板；导出保留其他模板。格式或内容错误时不替换现有表单。“完整配置与组织设置”支持高级字段；点击应用后才更新表单，尚未应用的文本会阻止下载可用配置。草稿可保存未通过检查的内容，需要修复后才能正式导入。

编辑内容仅保留在页面内存，不写入浏览器长期存储，也不上传到服务端。刷新前请下载；退出时浏览器可能提示尚未保存。下载按钮发起浏览器下载，不保证操作系统已完成保存，请确认下载文件。

## 创建实际世界

下载的 `world-template.json` 与 `engine:template` / `engine:init --template-file` 使用相同的格式与校验器。将文件放在 `world-engine/`，创建 `output/` 文件夹，然后运行：

```sh
npm run engine:template -- --input world-template.json --template-id river-valley
npm run engine:init -- --template-file world-template.json --template-id river-valley --output output/my-world.json
```

模板编号以页面提示为准；Windows 可以用 `npm.cmd`。之后遵循 [ENGINE_QUICKSTART.md](ENGINE_QUICKSTART.md)，导入专用数据库、创建账户并启动服务。首次导入使用新世界编号与 expected-revision 0，不能覆盖现有试用世界。

## 技术边界

- 浏览器和 Node 使用同一份 `shared/template-validation.js`。物种目录来自内置物种，只公开编号与名称；行动规则默认值和校验函数也与服务端共用。
- 页面只读取静态目录，不调用世界写入、账户或命令 API。没有新的服务端配置上传端点。所有文本使用 DOM textContent/value，不执行输入的 HTML/脚本。
- 静态资源使用精确路径白名单、原有来源限流和 CSP。GET/HEAD 之外的请求被拒绝；资源请求不写入操作审计。
- 预览是配置中的初始地点和人物；不运行 tick，不生成完整存档，不估计服务器性能。seedTicks 预推进的结果以正式初始化为准。
- 组织和高级字段保留，可通过完整 JSON 编辑；当前没有运行中世界热编辑、拖拽地图、组织表单或自助上线按钮。
- 无新依赖，无 migration、运行版本或一致性协议变化。revision fence、幂等、限流、审计脱敏、提交后发布、重试不重放继续由现有引擎处理。

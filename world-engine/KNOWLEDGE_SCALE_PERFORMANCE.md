# 信息传播与状态复制的第二批性能优化

本层基于已验收的 441d2d0，继续处理人口增长时的重复工作。第一批测量保留在 RUNTIME_PERFORMANCE.md；此页的比较基线是已经优化过的 441d2d0，不能把两个批次的不同测量直接相加。

## 实现

- 记忆和信息索引：每次重建仅在局部 Map 中维护数组对应的 Set，替代重复 Array.includes。索引数组的首次出现顺序、重复 ID/标签、数值和字符串身份保持一致。增量插入仍读取当前数组；集合不进入 world，也不跨调用复用，外部编辑或恢复不会留下过期缓存。
- 传播连接：用最大堆保留排序最靠前的 K 条候选，避免完整排序。权重、localeCompare 和原始插入次序共同决定顺序；Unicode 排序相等时仍保持稳定性。全部候选依然去重并计入 linksCreated。只有临时选择数组受 K 限制；同地人物配对枚举及去重集合仍随人口平方增长，没有声称实现无限规模。
- 世界复制：普通有限 JSON 数据在一次递归中验证、分离引用并规范对象键，省去字符串转换和再解析。数组顺序、空洞/undefined、负零、共享引用和 __proto__ 自有字段保持原有结果。getter、toJSON、Proxy、自定义原型、深层结构和特殊值回退到旧捕获路径；选择快路径不执行用户 getter 或 Proxy trap。每 tick 的修复和规范化仍执行，恢复门禁不变。

## 同机实测

Windows / Node 22.23.3，同一机器依次运行，两版本各三次。以下报告真实毫秒，不涉及数据库提交、网络或 API 吞吐。

| 测量 | 441d2d0 中位数 ms | 本层中位数 ms | 速度比 |
|---|---:|---:|---:|
| 128 创始人物，第 20 tick 同一输入再推进 10 tick | 5,957.667 | 5,147.139 | 1.16x |
| 同一第 20 tick 世界规范复制 10 次 | 709.441 | 350.781 | 2.02x |
| 3000 条记忆，完整索引重建 10 次 | 248.616 | 14.064 | 17.68x |
| 600 人同地，359400 个唯一候选中选择 120 条 | 1,136.628 | 250.122 | 4.54x |

完整 tick 场景耗时减少约 13.60%；单项速度比不是整个引擎的提速倍数。组件测量各预热两次后测三次；完整 tick 每次在独立进程从同一文件读取，计时不含启动、读取和最终摘要。

完整 tick 三次原始值（ms）：旧版 6030.9798 / 5957.6671 / 5945.5786；本层 5471.8762 / 5106.2779 / 5147.1385。六个输出均为 7,237,808 bytes，SHA-256 为 `acabe58e74fca86311df627ffdc15c524ebadb1c53b120514c482e1305594aae`。三项组件输出摘要也逐一相同。

交接包 benchmarks/ 保存原始输入、完整 tick 驱动和 benchmark-round2-components.cjs。按其中 README.md 克隆 bundle 中的当前/441d2d0 两版、安装各自锁定依赖，再逐个测量；不要同时运行其他测试或把 CPU 采样开启后的耗时混入基准。evidence/final 保存原始结果。

实际世界各系统耗时仍使用 `npm --prefix world-engine run engine:profile -- --input SAVE --ticks 10 --output NEW_REPORT`。输入文件只读，报告不写出原始世界或账户资料，输出必须为新文件。

## 验收

本层新增两份回归脚本，完整发现分母从 108 增为 110：750 轮记忆/信息索引重建对照，880 组传播连接选择对照，以及稠密连接统计、Unicode 并列、重复 ID/标签、浮点 limit、缓存生命周期验证。扩展规范复制测试，验证 getter/toJSON/Proxy 调用次序、撤销 Proxy、继承数组项、深层 JSON 和原型 setter 只执行原有次数。

全量回归、Node 20/22、真实 PostgreSQL、100/1000 tick、故障恢复和六组规模长测继续执行。规模门禁仍要求完整世界摘要等于上一批接受的三个固定摘要，32 MiB 门禁和所有 migration 原样保留。最终状态以对应交付提交的实际日志为准。

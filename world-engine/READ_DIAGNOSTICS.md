# 已提交世界读取诊断

`GET /durable/worlds/:worldId/admin/operations` 的 `reads` 字段报告当前 HTTP PostgreSQL adapter 的读取观测。GM/Admin 经过原有认证、账号限流和队列 revision fence 后才可读取。普通玩家、匿名请求、并发撤权均不能读取诊断；诊断故障不会改变已经成功授权的管理响应，不支持此接口的 adapter 返回 `null`。

这些是进程内计数，覆盖该 adapter 读取的所有世界，重启后清零。不代表数据库全局、运行器 Worker 或某个玩家的请求总数。认证读取也计入，管理查询自身的认证读取通常包含在返回值中。诊断不缓存授权、不新增 SQL 查询、不放宽心跳或错误门禁。数据库不可用导致认证失败时，不能绕过认证读取诊断；恢复后可查看保留的最近故障。

| 字段 | 含义 |
|---|---|
| requests / completed / failed | `loadWorldView` 调用、成功返回和异常返回次数；不存在的世界计入 completed 和 missing。 |
| active / peakActive | 正在进行的读取及本 adapter 历史并发峰值。成功、异常、关闭时在途完成均结清 active。 |
| cacheHits / sharedLoads / payloadLoads | 选择已校验缓存、加入同一存档的在途处理、发起完整存档查询的次数；是路径选择次数，后续事务仍可能失败。读取头部前失败或世界缺失不归入这三项。 |
| duration | 全部已结束调用的最近、最长和累计耗时（毫秒）；含连接等待、SQL、共享等待、校验及事务完成/回滚，不含 HTTP 网络、投影或审计写入。并行请求各自计时，累计不是墙钟持续时间。 |
| lastPayload | 最近一次完成下载、恢复和冻结的存档文本 UTF-8 字节数，以及查询/传输和恢复校验耗时；不是数据库磁盘大小或进程内存。共享读取只记录一次。它不是最后一个 HTTP 请求，也不保证随后只读事务提交成功。 |
| lastFailure | 最近异常的固定分类、当时阶段、距今毫秒数。后续成功不清除这一历史记录；阶段 shared 表示该请求正在等待另一个完整读取。 |

使用单调时钟计时，不与世界 tick 或系统日期绑定。只保留固定数量的数字和两条摘要，累计数值有上限，不按账号、世界或异常文本建立集合。没有令牌、URL、账号/角色 ID、输入、摘要、连接串、SQL、原始错误或堆栈。API 再做字段白名单与数值检查，兼容自定义 adapter 的不可信诊断返回。

分类包括数据库超时、连接不可用、迁移要求、关闭、存档损坏、归档、参数错误、数据库查询错误和未分类错误。它说明实际观察到的读取失败，不推断 CPU 饱和或历史 500 的唯一根因。成功读档后仍显示历史故障，并不表示当前不可用。

控制台的“管理与审计”增加中文世界读取诊断。操作开始立即显示等待状态，超过三秒显示首次读档/服务唤醒提示；完成、失败、退出和页面离开时清除。没有虚构进度百分比、自动重发指令或取消幂等保护。原 20 秒请求超时保持。

验证：新增固定时钟计数/脱敏回归；真实 PostgreSQL 原 14 组读取门禁增强并发、损坏、超时、恢复、关闭、HTTP 管理读取的诊断断言；原管理 API 增加权限、并发撤权、自定义诊断失败的覆盖。新增诊断回归由普通测试发现器自动收录；SQL 专项组数不变。发布仍要求 Node 20/22、100/1000 tick、耐久、三档规模恢复与 pipefail 日志核验，最终通过状态以对应提交的交付证据为准。

无新依赖、数据库 migration、存档格式或运行版本变化。运行方式：`npm test`，`npm run test:postgres:read-view`；SQL 测试仍需独立 `_test`/`_ci` 数据库。

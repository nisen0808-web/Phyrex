# HTTP 在途容量保护

来源和账户的窗口限流不能限制同时等待数据库的任务数量。数据库或审计写入变慢时，HTTP 响应已经送达的请求仍可能持有审计任务。现在统一服务与独立 durable API 在进程内限制这些任务，默认最多 256 个。

`createDurableCommandApiServer({ maxInFlightRequests })` 接受 1–10000 的整数。CLI 通过 `WORLD_ENGINE_COMMAND_API_MAX_IN_FLIGHT_REQUESTS` 配置；统一 `engine:serve` 也沿用该变量。配置在接管数据库资源之前校验，没有新依赖、SQL migration、存档或运行器版本变化。

## 请求和恢复

每个任务从读取请求开始占用名额，经过授权、SQL 操作和响应后的独立审计，直至成功或失败处理完成才释放。半截上传占用名额，客户端断开后释放。审计失败只计入已有失败统计，不改变已送达响应；它也会释放名额。

名额用满时，新的普通请求先消耗已有来源限流额度，然后返回 503 `service_unavailable`、`Retry-After: 1`、`Connection: close` 和新的 `X-Request-Id`，不读取世界、不验证会话、不写命令，也不排入新的审计。若来源额度已经耗尽则返回原有 429。过载拒绝不会消耗账户配额，因为尚未认证。

容量拒绝没有匿名 SQL 审计，避免把数据库拥塞继续扩大；在进程内累计拒绝次数。已接收请求的审计和正常关机等待规则保持原样，不自动丢弃或改写为 500。超过 CLI 总关机期限仍按原有规则失败退出，不承诺突然退出时审计无损。

客户端应保存原 command ID，等待后查询或以相同内容重试。503 不是此前同编号请求未提交的证明，不能改用新编号自动执行一次。数据库恢复后任务完成会自然释放名额，不自动重放任何业务请求。

## 健康与诊断

配置健康回调时，精确的 `GET /health/live` 不占任务名额，不访问数据库或写审计，并继续受来源限流。请求带查询参数或使用其他方法不会取得这一例外。`/health/ready` 在满载时返回 503，不向数据库追加探针。

`api.requestStats()` 返回 `{ inFlight, limit, rejected }`，`api.options.maxInFlightRequests` 返回配置。GM/Admin 的 `/admin/operations` 在授权后增加同形状的 `requests`。inFlight 包括当前诊断请求和响应后的审计任务；拒绝次数重启清零，观测与 SQL 快照不是同一时点。普通玩家不能通过该接口读取诊断。完全满载时诊断也返回 503，等待任务释放后再读取。

## 验证和边界

普通回归覆盖并发授权等待、过载不访问存储、响应后的审计占用、失败释放、上传中断、健康探针、来源限流和相同编号重试。真实 PostgreSQL 命令 API 专项新增两组：用实际 SQL 锁阻塞审计插入，确认响应后仍占名额、新请求无法写入；释放锁后确认恢复及同编号幂等，且只产生原请求和重试的两条审计。该专项完整门禁由 9 组增至 11 组，普通 discovery 为 138 项，SQL 17 专项共 161 组/Node 版本。

统一 engine:verify 的读视图完成标记同步为 #84 已要求的 14 组，普通回归检查所有 SQL 完成标记与必跑 CI workflow 一致。all 当前为 23 个门禁；退出码、实际完成标记及 bash/pipefail 继续保留。最终通过情况须读取对应提交日志。

该上限控制本进程的请求任务，不是全站内存、socket 数、数据库空间或多实例全局限制；HTTP 头部读取和未发送完整头部的连接仍依赖 Node 超时及网关。单写入器、revision fence、命令事务确认与幂等均保持原契约。

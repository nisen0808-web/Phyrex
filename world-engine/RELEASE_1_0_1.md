## 兼容性与演化基线

组织修复改变新建世界的实际归属和事件，后续行为与 1.0.0 不应再假定逐字段相同。三种规模场景仍为 4/12/32 初始人口、1000/600/300 tick，保留出生、死亡、后代、有限数值、全部独立恢复点和 32 MiB 上限。基线变更记录保留旧摘要、新摘要、原因及本地测量结果，Node 20/22 独立验证新结果；没有降低门禁或用改断言掩盖容量失败。

修复仅影响新建世界的创始成员初始化；加载旧存档不会猜测人物历史或回写所属组织。已有世界如需修复成员关系，应先停止写入器、备份并确认真实归属，再由受信任宿主通过组织 API 和正常 checkpoint 保存；不能批量覆盖所有历史成员身份。过程保留的显式 false 覆盖和自定义处理器扩展从本版开始按调用者意图生效。

本版没有改变公共玩家输入协议或已发布 SQL；正常停止旧服务、备份后换用本版并启动即可。不得同时运行旧、新写入器。旧 applied 命令不重放。完整 v1–v4 到 v5 的显式升级规则仍见 DURABLE_INVENTORY.md。

## 验收与交付

新增 review-followups-test.js，discovery 总数为 126。保留 16 个真实 PostgreSQL 专项；quickstart 的 6 组中加强成员关系持久化和真实 HTTP 管理统计验证。服务专项继续验证隔离 Worker、启动/停机/恢复、权限、数据库不可用、revision fence 和故障停收。完整验收仍要求 14 个 CI 作业当前提交全部通过、实际完成输出和 pipefail 校验。

隔离环境采用 GitHub CI 的一次性 PostgreSQL 18 容器与随机测试 schema，Node 20/22 分别执行。这是可复现的隔离测试环境，不代表已经建立常驻测试站点或生产托管。运行和上线准备见 ISOLATED_VALIDATION_RUNBOOK.md。

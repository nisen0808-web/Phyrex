# 长期世界运行的容量边界

`runtime/engine-v1-profile.js` 提供显式的长期运行配置，`engine:init` 创建的世界默认使用它。既有世界不会被静默改变配置，运行器仍以配置摘要阻止不同规则下的意外恢复。终态机会/冲突、历史事件、信息、记忆等此前已有容量控制。

新增因果记录 `retention.maxCausalityRecords`：将最旧连续前缀汇总为各实体的累计分数，只保留最近明细。叙事评分使用汇总加剩余明细，顺序与原来的逐条加法一致，包括浮点数的相加顺序。待处理事件、动作和未结束流程引用的 cause ID 会阻止清理到该位置，`world.causalityArchive.overLimit` 显示因此超出的数量。历史累计分数随实体数量增长，不随 tick 明细数量增长。原始明细被清除后不能用汇总重建完整因果链，需要保留之前的存档/备份。

新增契约 `contract.maxTerminalContracts`：只清理 completed/broken/cancelled/expired，保护未结束流程指向的契约；重建全部索引，保留生命周期累计计数。未知状态保留。`world.contracts.retention` 显示受保护数量和超预算数量。

新增流程 `process.preserveActive: true`：活跃、未知状态、仍被未结束流程或活跃机会引用的记录不会因为预算被删除。只清理未被引用的 resolved/stalled 记录。`world.processes.capacity` 显示当前数量、受保护数量、总量超限和非活跃数量超限。旧世界未启用此选项时沿用原有硬上限语义；v1 初始化配置显式启用保护模式。

事件记忆、因果记录和契约记忆改用世界递增 ID 分配器，修复滚动数组长度固定后同 tick 重复生成 ID 的问题。裁剪不回收 ID，不额外消耗随机数。该修复影响旧运行器继续运行时的记录 ID，所以比较新旧引擎版本的历史摘要时不能假设相同版本外的字节结果。

容量不是人口上限。活跃实体、关系、家谱、组织、账户和幂等凭据会随世界规模增长；不通过删除活跃活动伪装固定内存。默认 PostgreSQL checkpoint 上限为 32 MiB，超过时会明确拒绝保存，运行器不发布未提交状态。运行前按实测的世界规模选配置，查看容量压力；若业务需要更大世界，需要配置更大 envelope 上限或设计分区。

`test:engine:scale -- small|medium|large` 是专门的长运行门禁，分别验证 4/12/32 个创始人口、1000/600/300 tick，三个固定 seed。为覆盖出生、死亡、后代，测试将一年加速到 8 tick，出生率设置为 0.01；它不是默认世界的自然时间参数，也不把耗时换算成生产吞吐。每 100 tick 留下体积、活跃人口、流程压力、耗时样本，恢复点比较整个世界摘要，有限数值、索引和默认 checkpoint 体积均为硬断言。新 CI 在 Node 20/22 上运行全部三个场景，保留明确完成标记和 pipefail。
